## Items

### 1. Control appears under "Integrations" in the editor menu

v0.8.0 tried `category: 'integrations'`, the wrong key. BV splits the control menu on `type === 'integration'` (`src/editor/inspector-controls/controls-panel-header.js:67-70`). But `src/utils/get-enabled-controls.js` removes any integration control unless `variables.integrations[ settingSlug ].active` is truthy. So both are required:

- JS: add `type: 'integration'` to the `blockVisibility.controls` registration.
- PHP: filter `block_visibility_rest_variables` to set `$variables['integrations']['acf_date_time'] = array( 'active' => function_exists( 'acf' ) );`.

The settings page's "Default controls" list (`src/settings/visibility-controls/general/index.js`) also uses `getEnabledControls`, so the PHP filter is what keeps the control in that list too. Verify both places.

### 2. Label and icon

- Rename the label to "ACF Date & Time" (matches BV's "Date & Time"; still sorts next to "Advanced Custom Fields"). The label isn't stored in block attributes, so no migration. Update the panel heading to match.
- Add an `icon` from `@wordpress/icons` (calendar or clock); BV renders `control.icon` next to integration controls.

### 3. Settings-page panel

BV's Settings → Visibility Controls → Integrations section has `<Slot name="VisibilityControlsIntegrations" />` (`src/settings/visibility-controls/integrations/index.js:74`) and there is a `blockVisibility.VisibilityControls` `withFilters` hook. Add a panel there with a global enable toggle for `visibility_controls.acf_date_time.enable`, modeled on BV's own ACF settings panel (`src/settings/visibility-controls/acf/`). Before this there was no UI to disable the control globally. Needs a new settings-page script enqueued on BV's settings screen (`admin_enqueue_scripts`); check how BV exposes settings state to Fill components.
